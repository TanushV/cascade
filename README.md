# Cascade

[![CI](https://github.com/TanushV/cascade/actions/workflows/ci.yml/badge.svg)](https://github.com/TanushV/cascade/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

> **Independent project:** Cascade is not affiliated with, sponsored by, or endorsed by the Pi project, Mario Zechner, or Earendil Works. “Pi” identifies compatibility with the upstream runtime.

Cascade is Pi with an additive one- or two-model orchestration layer. It preserves Pi's native TUI, `/login`, `/model`, sessions, extensions, commands, and active tools, then adds an economical worker, an on-demand expert, evidence handoffs, adaptive escalation, verification, privacy controls, budgets, and replay-gated harness learning.

Cascade targets `@earendil-works/pi-coding-agent@0.84.2` at upstream commit `59a71b235dadb4ad0d67557a8abb0aaa093e68b4`. A separate global Pi install is not required.

## Install

Requirements: Node.js `22.19.0` or newer and npm.

```bash
npm install -g github:TanushV/cascade --ignore-scripts
```

Verify:

```bash
cascade --version
cascade self-test
cascade runtime
```

Expected shape:

```text
cascade 0.3.0
bundled-pi 0.84.2

Cascade self-test passed.
```

## Start normally

No initialization or configuration file is required just to open the agent:

```bash
cd /path/to/your/repository
cascade
```

Use `cascade --approve` when you intentionally trust project-local Pi/Cascade resources.

Cascade now starts the native Pi TUI first. A missing key, unavailable expert, invalid optional profile, or disallowed Contributor endpoint cannot prevent the TUI from opening. Inference through a disallowed endpoint remains blocked, while `/login`, `/model`, `/cascade-setup`, and the rest of Pi remain usable.

Legacy `.cascade/config.json` files generated by Cascade 0.2 are migrated so their disabled Contributor default does not hijack startup.

## Configure inside the TUI

Run:

```text
/cascade-setup
```

The wizard configures:

- single or dual mode;
- native Pi worker selection or a fixed worker model;
- expert model;
- worker and expert reasoning levels;
- inherited Pi tools or an explicit role allowlist;
- automatic expert consultation;
- session and expert budgets;
- repository privacy classification and Contributor consent;
- session-only, project, or global persistence.

Useful commands:

| Command | Purpose |
|---|---|
| `/cascade-setup` | Complete role-aware TUI setup |
| `/cascade-worker` | Choose the worker from Pi's model registry |
| `/cascade-expert` | Choose the expert independently |
| `/cascade-auth [provider]` | Prepare Pi's native `/login` flow |
| `/cascade-role worker\|expert` | Switch the active parent-session role |
| `/cascade-mode single\|dual` | Change orchestration mode |
| `/cascade-tools` | Show active Pi tools and the parity baseline |
| `/cascade-compaction` | Edit global Pi compaction limits |
| `/cascade-update` | Update Cascade from GitHub inside the TUI |
| `/cascade-consult <question>` | Run a bounded read-only expert consultation |
| `/cascade-takeover [objective]` | Run one explicitly authorized expert editing episode |
| `/cascade-evidence [count]` | Inspect the evidence ledger |
| `/cascade-verify` | Discover and run repository checks |

Pi's own commands remain available, including `/login`, `/logout`, `/model`, `/settings`, session commands, themes, and commands supplied by other extensions.

## Authentication

Use Pi's native login flow inside the TUI:

```text
/login openrouter
```

You may sign in through OpenRouter or enter an API key. Pi stores credentials outside the repository in its auth store.

Environment variables also work:

```bash
export OPENROUTER_API_KEY="..."
export MODEL_API_KEY="..."   # bundled Meta Model API profile
cascade
```

Do not put literal keys in `.cascade/config.json`.

## Models and tools

The worker defaults to **native Pi selection**. This means Pi's current model and native `/model` picker remain authoritative until you deliberately choose a fixed worker.

In dual mode, the expert is configured separately. Expert consultations and reviews are read-only. A takeover may edit only when explicitly authorized and permitted by the expert's configured tool list.

Cascade does not replace Pi's active worker tools by default. Tools from Pi and other extensions remain active. Restriction occurs only when you deliberately select an explicit allowlist.

## Optional configuration files

The TUI writes these for you when requested:

```text
Project: .cascade/config.json
Global:  ~/.config/cascade/config.json
```

Configuration is optional. Files are merged in this order:

1. built-in defaults;
2. global Cascade config;
3. trusted project Cascade config;
4. explicit config;
5. environment and CLI overrides.

See [`docs/configuration.md`](docs/configuration.md) for the complete schema.

## Global compaction limits

Inside the TUI:

```text
/cascade-compaction
```

Or from the shell:

```bash
cascade compaction show
cascade compaction set \
  --enabled true \
  --reserve-tokens 24000 \
  --keep-recent-tokens 32000
```

These values are written to Pi's global `~/.pi/agent/settings.json` and apply to new Cascade and Pi sessions.

## Updates

After installing 0.3.0 once, future updates are one command:

```bash
cascade update
# alias: cascade pull
```

Or from the TUI:

```text
/cascade-update
```

Restart Cascade after an update. `cascade update --dry-run` shows the exact update invocation without changing anything.

## Privacy boundary

A configured Contributor model is denied unless both conditions are true:

```json
{
  "privacy": {
    "classification": "public",
    "allowContributor": true
  }
}
```

That policy may block inference through the selected Contributor endpoint, but it does not lock the operator out of the TUI. Secret redaction and denied-path filtering are defense in depth, not a substitute for a real sandbox.

## Development and validation

```bash
git clone https://github.com/TanushV/cascade.git
cd cascade
npm ci --ignore-scripts
npm run ci
```

The suite includes unit, integration, package-install, Git-source, privacy, routing, persistence, updater, compaction, and **real pseudo-terminal TUI** coverage. One TUI test starts the actual bundled Pi interface without credentials, reproduces the old blocked configuration, verifies native tools and commands, opens Cascade setup, compaction, update, Pi model, and Pi login interfaces, and exits normally. A second test runs a complete offline agent turn through a localhost OpenAI-compatible model, executes Pi's real `write` tool, returns the tool result to the model, and verifies the final response and edited file.

Live model inference requires your own provider credentials and can be checked with:

```bash
cascade probe worker --approve
cascade probe expert --approve
```
